### 热键功能 Bug 修复（第二轮）
- **Settle 定时器无限重置 Bug**: flagsChanged 事件频繁触发导致 scheduleSettle 反复 cancel+重建，定时器永远到不了。用 settleScheduled 标志位防止重复安排
- **修饰键 keyDown 误触发防误触**: Shift/Ctrl 键本身同时产生 flagsChanged+keyDown，导致 cancelledByShortcut 错误置 true。加了 modifierKeyCodes 白名单排除
- **defaultTap 拦截问题**: 从 .defaultTap 改为 .listenOnly，避免拦截系统事件导致修饰键行为异常
- **启动顺序**: 将 hotkeyMonitor.startListening 提到 requestPermissions 和 WhisperBridge.initialize 之前，确保 event tap 尽早注册
- **WhisperBridge 路径修复**: .app bundle 模式下 findProjectDir 返回的是 .build/ 而非项目根，修正为上走两层
- **线程安全**: 所有事件处理 dispatch 到主线程，避免 RunLoop 线程和主线程竞态
- 端到端自动化测试通过: Event tap→热键触发→录音→停止 全链路正常

### 热键功能 Bug 修复（第三轮 - v3 彻底重写）
- **根因定位**: `DispatchQueue.main.async` 导致 flagsChanged 事件被批处理——按下和松开事件在同一 RunLoop 迭代中处理，settle 被安排后立刻被后续事件取消
- **核心修复**: 移除所有 `DispatchQueue.main.async`，事件直接在回调中处理（CGEventTap 回调已在主线程）
- **Settle 机制重写**: 从 `DispatchWorkItem + asyncAfter` 改为时间戳+轮询定时器——记录 `bothHeldSince` 时间戳，30ms 定时器轮询检查 elapsed >= 0.1s
- **双重监听**: 同时注册 CGEventTap (defaultTap) + NSEvent.addGlobalMonitorForEvents，CGEventTap 为主、NSEvent 为备
- **defaultTap 恢复**: 从 listenOnly 改回 defaultTap（某些 macOS 配置下 listenOnly 不传递 flagsChanged），回调中 return 原事件不拦截
- **文件日志**: 所有事件写到 /tmp/typeless_hotkey.log，方便用户端诊断
- 自动化测试全部通过: 正常按住触发 ✅ / Ctrl+Shift+Tab 防误触 ✅ / 按住1秒录音 ✅
